# 一键导出排查包（2.5.1 已正式发布）

旧版已经在任务中保存录制日志，但需要用户手工寻找文件。[2.5.0 正式版](https://github.com/luckcatlin2000/luckcaty-cut-dota2/releases/tag/v2.5.0) 增加醒目的红色“导出排查包”入口，将错误说明与已有诊断文件保存为 ZIP。2.0.0 安装包不包含这个入口；2.5.0 已发布且公开下载已核验。

2.5.1 延续 R3 的仅高光发行范围。排查包入口用于高光主程序；WTF、剧情与录像分析均尚未正式提供，三个模块入口统一提示，当前不启动模块。WTF 本地候选保留但不随本次发行，未正式提供不表示独立录像分析不存在。

## 用户操作

1. 导出失败并完成任务收尾后，在“导出视频”窗口的错误说明旁点击红色 **导出排查包**。
2. 选择 ZIP 的保存位置。完成后软件显示保存路径，可点击 **打开所在文件夹**。
3. 将 ZIP 手动发送给维护者。软件不自动上传或发送。

已经关闭软件时，先从“最近任务”重新打开原任务，再进入“导出视频”，从窗口下方的入口导出历史记录。不要求再次启动游戏或复现失败。“复制排查信息”仍可使用。浏览器界面预览不能保存 ZIP，请在桌面程序中操作。

ZIP 保存到用户在系统保存窗口中选择的位置，并非固定写入录像文件夹。软件显示实际路径，可打开所在文件夹；默认文件名包含任务编号和唯一标识。取消保存窗口不生成文件，同名文件不会直接覆盖；打包失败单独显示原因，不替换原来的录制错误。

## 包含内容

- `report.txt`：当前界面的版本、任务、错误原文、阶段和片段进度。重开任务后当前界面可能没有旧错误原文，应结合历史日志阅读。
- 最近的录制日志，以及启动检查、取消、失败或成功的导出尝试摘要。
- 任务内已有的恢复状态、采集诊断和质量检查 JSON。
- `bundle.json`：包清单、来源文件大小、截断标记、缺失文件与限制说明。历史记录不存在时仍可导出当前报告，不会宣称已恢复不存在的日志。

收集范围仅限当前任务中约定的位置：

```text
render/logs/render-*.jsonl
render/attempts/attempt-*.json
render/cache/<16位指纹>/state.json
render/cache/<16位指纹>/segments/<片段目录>/capture-diagnostics.json
render/cache/<16位指纹>/segments/<片段目录>/quality.json
director/edit-plan.json
```

排查包不包含 DEM、图片帧、音频或视频。仅收集当前任务中约定位置的诊断文件，不读取账户配置。错误文本和日志可能包含本机文件路径，发送前可自行查看包内内容。

## 记录与限制

新录制约每 5 秒记录已采集帧数、目标帧数、经过时间与最后进展，超时、取消或其他失败时保留最后计数。导出尝试摘要覆盖开始、早期失败、取消与完成；若强制结束或断电，可能只留下开始状态。

**已发布的 2.5.0 没有修改原生逐帧导出的固定超时策略。** 新日志用于区分持续慢速推进和长时间停滞；“需要若干帧，只得到若干帧”不代表显卡不支持，也不能仅凭一个计数确定根因。录制画质、60 FPS、镜头、原声与时间窗保持原有设置。

2.5.1 已正式发布，针对持续出帧仍被旧期限终止的情况调整等待策略；新增 `timeoutReason`、首帧/停滞/总上限阈值。完整发布验证与工件核验通过，自动验证和实机验收分别记录在 [采集等待修复说明](CAPTURE_WAIT_RECOVERY.md)；2.5.0 安装包仍使用旧规则。

最多收集最近 8 份录制日志、8 份尝试摘要、4 组缓存，每组最近 32 个片段诊断。单份日志最多保留末尾 4 MiB，并尽量保持完整行；单份 JSON 上限 1 MiB，诊断源文件合计上限 32 MiB，源文件数上限 256。包内报告与清单另行写入，ZIP 大小不保证恰好低于 32 MiB。

截断、缺失、超限或无法读取的文件会在包清单与界面说明。不会跟随链接或任务状态中的任意外部路径，不移动或清理原有日志和媒体。排查包可能含本机路径、片段说明或游戏控制台原文，发送前可自行查看。

旧版没有保存的采集进度无法补回。断电或强制结束可能留下“已开始、未结束”的尝试记录；这不等同于一次成功导出。

排查包功能已随 2.5.0 正式发布，2.5.1 的采集等待修复已正式发布。自动回归和界面检查不等同于 Dota 实机导出验收。

第一轮（R1）排查包与高光布局曾完成完整验证：196 项 Rust、74 项前端测试通过，8 项外部条件测试 ignored，格式、严格 Clippy 与前端生产构建通过。ZIP 回读、缺日志、截断、链接排除、保留原文件及重复请求有覆盖。

R1 当时的 1100×680 与 800×600 待导出、失败、续录共六种界面组合、七片段滚动有检查记录；这些界面结果不能替代新增独立 WTF 后的 R2 GUI 验收。

R2 完整验证已退出 0：210 项 Rust 通过、9 项外部条件测试 ignored，85 项前端测试及前端生产构建、格式和严格 Clippy 通过。真实 DEM 默认跳过的回归另行运行 1 项通过；匿名样本的故事分析与主备方案导入已验证，源录像未变。

以上 R2 的双 EXE 构建、哈希与真实只读样本只属内部预览历史，不是 R3 发行物；原 WTF 候选保留。R1/R2 界面结果不能替代 R3 验收。

R3 完整验证退出 0：213 项 Rust 通过、9 项外部条件测试 ignored，86 项前端测试及前端生产构建、格式和严格 Clippy 通过。单主高光程序生产构建及仅高光范围已核对，不含模块 EXE 或模块清单；正式发布、公开下载、安装包门禁、签名/篡改拒绝及隔离无输入冷启动健康检查通过。本轮未另跑真实 DEM，也未进行新的视觉、鼠标、原生保存窗口或游戏实测。
