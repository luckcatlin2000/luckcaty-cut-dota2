# 独立 WTF 剪辑模块（本地开发候选，未正式提供）

## R3 官方发行范围

此次 GitHub 仅提供高光时刻，WTF 不随主程序发布，也不由当前“WTF 剪辑”按钮启动。WTF、剧情与录像分析三项在中央 `module-catalog.json` 中均为 `released:false`，前后端统一门禁和提示。录像分析未正式提供不等于程序不存在或本机未安装。

未来 WTF 正式提供、目录状态开放，并检测到兼容安装后，用户点击按钮才会启动。以下内容描述 R2 内部预览的真实开发能力，不是当前正式安装或运行指南；原 WTF 候选及其草稿继续保留，不删除。

开发构建已隔离：默认 Cargo/Tauri 构建不启用内部 WTF 二进制；维护者单独检查该程序时须显式启用 `wtf-module`。入口源码放在 `src-tauri/src/wtf_entry.rs`，避免安装打包器把 `src/bin` 中的开发程序自动收进高光安装包。正式构建还要通过实际 NSIS 文件载荷白名单检查。

R3 完整验证退出 0：213 项 Rust 通过、9 项外部条件测试 ignored，86 项前端测试及前端生产构建、格式和严格 Clippy 通过。单主高光程序构建与候选范围核对通过，不含 WTF EXE 或模块清单。R3 未另跑真实 DEM，也未进行新的 UI、鼠标或游戏实测；本次结果不将内部 WTF 候选改为正式提供。

WTF 剪辑与录像分析是两个独立程序。候选入口为 `WTF剪辑/WTF剪辑.exe`，拥有自己的任务和草稿；录像分析保留原来的数据分析与“导演方案”，不以改名代替 WTF 功能。高光主程序不恢复旧的默认/WTF 双模式执行。

R2 内部预览曾采用以下布局验证同版本交接。该双 EXE 目录不随 R3 高光候选或本次主程序发行提供：

```text
猫猫的剪辑小助手.exe
WTF剪辑/
  WTF剪辑.exe
  module.json        （toolId 为 wtf）
```

## R2 内部候选已实现的流程

1. 在独立 WTF 程序中选择本地 DEM，进行完整故事分析；原录像只读，分析不启动游戏。
2. 按英雄和“全部 / 趣味 / 精彩 / 失误”筛选，查看故事证据、置信度、复核提示、节拍、场次与机位建议。
3. 采用故事，将真实机位加入本模块录制清单。可调整场次顺序、移除场次、编辑同步时间、录制英雄与玩家/跟随视角。
4. 自动或手动保存独立草稿，重新选择同一份录像后继续编辑。草稿与源录像和故事来源核对，不覆盖高光或录像分析的草稿。
5. 选择“导出方案 JSON”保存 1.2 同步方案，或点击“交给高光剪辑”创建独立录制会话。在高光窗口核对后，由用户手动开始导出。

当前确定性故事规则只有以下真实范围；空结果明确显示为空，不从孤立动作猜测玩家意图：

| 类型 | 实际规则与证据 |
|---|---|
| 趣味 | 森海飞霞临时树被补刀斧反制，要求临时树创建、指定树指令和删除的验证链；可整理重复互动与已有反应上下文 |
| 精彩 | 有录像归属依据的英雄击杀链，保留技能起手、击杀结果、铺垫与对应素材 |
| 失误 | 同一英雄买活后 90 秒内再次最终死亡，排除重生；间隔较长时标记人工复核，不把时间相邻直接当成动机结论 |

建议切换窗口、构图用途与备用机位是剪辑素材和提示，不等同于自动完成电影运镜、特效或多机位成片。软件不自动生成文案、配音、BGM，不调用模型或云端生成服务。

## 1.2 同步方案如何保留主备机位

方案使用 `d2h.timestamp-plan/1.2`，提供真实源录像 SHA-256、比赛身份、录像时间基准，以及每个素材的事件锚点。

| 字段 | 含义与校验 |
|---|---|
| `camera_mode` | 仅接受 `player_perspective` 或 `hero_chase` |
| `take_group_id` | 同一场次的分组；进入主程序时规范为短标识，保持同步关系 |
| `take_role` | `primary` 或 `alternate`；每组必须且只能有一个主机位 |
| `include_in_final` | 主机位为真，备用为假；备用不增加默认成片时长 |
| `anchor` 与时间范围 | 同组使用相同真实锚点、候选身份和时间窗，允许不同录制英雄 |

每个素材保留独立来源 ID，同组使用共享候选 ID；不能把所有机位展平成默认主机位。时间先按现有 30 Hz 编辑网格规范，再选择共同事件锚点，并通过实际导入器自检。

普通 1.0/1.1 方案保持原来的单主机位语义，不能携带 1.2 新字段。错误源文件、英雄、相机、主备组合或不同步时间窗会被拒绝，原有草稿保持。

主程序已修复导入元数据保全：合法导入片段不会因缺少普通候选 ID 被误判为旧草稿冲突；恢复、编辑与保存保留来源及锚点。复制或新增片段会生成独立的 64 字符十六进制来源 ID，并保留共享候选关系，避免后续交接误更新用户副本；手动换候选时同步清除旧来源。

## 独立任务与录制交接

- WTF 草稿保存在本模块任务内的 `director/wtf-draft.json`，与旧双模式草稿分开。
- 每次交接在 WTF 任务的 `handoffs/session-<唯一标识>/` 中建立方案、回执和独立录制任务。
- 高光剪辑只校验并执行录制方案，不重新启用旧 WTF 模式，不覆盖用户原 `jobs`。
- 缺少兼容的相邻主程序时保留方案与回执并明确提示；录制需要支持 1.2 的新版高光程序。
- 旧 WTF 草稿仍保全但不自动执行；本模块新草稿按自己的来源规则恢复。
