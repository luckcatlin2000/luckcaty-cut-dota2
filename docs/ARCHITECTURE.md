# 独立高光剪辑架构（2.5）

## 主流程

```text
本地DEM（只读） → 击杀事件与10人阵容 → 高光候选
→ 人工复核时间/英雄/镜头 → 保存默认高光草稿
→ 用户开始导出 → 自有离线Dota原生JPG/WAV采集
→ FFmpeg编码/合并/质检 → MP4、源素材、恢复状态与诊断
```

桌面高光路径只读取所需战斗日志，不自动生成完整实体/树木或创意导演分析。完整解析与检测库可供独立模块复用，代码存在不代表桌面已提供对应入口。

## 模块分工

- **剪辑助手**：高光选片、精确时间、玩家视角/英雄跟随、普通/干净画面、原声、逐段录制和恢复。只执行默认高光草稿，旧WTF槽按原文保全。
- **录像分析**：完整数据、复杂场景、WTF导演与制作方案。具体可用规则、模型与接口以该模块版本声明为准。
- **剧情等上游软件**：产生明确片段方案，由通用适配器校验录像身份、时间依据和英雄后交接。

外接模块通过`maomao.module/1`描述入口，只在用户点击时发现并打开，不在后台轮询。片段交换使用`d2h.timestamp-plan/1.1`。详见[录制交接](RECORDING_INTEGRATION.md)与[设计方向](MODULE_DESIGN.md)。

## 采集与数据边界

回放控制只连接本机白名单控制端口；仅用户开始导出后启动自己的`-insecure`离线Dota，不接管已运行游戏。导入、分析和编辑不启动Steam或Dota。

采集保持游戏原分辨率、60 FPS、JPEG质量100及游戏原声。成片时长依据计划和有效帧数，不把墙钟耗时当视频时长。帧序列先位于Dota的`game/dota/movie`，之后按预录帧和目标帧裁切编码。多个同步机位的候选和时间窗一致，备用机位不增加默认成片时长。

完成片段需通过媒体校验、指纹与内容哈希检查才能用于恢复；保留旧素材不等于一定可复用。画面采集或镜头逻辑变化会改变采集管线指纹。

## 诊断与交付

每次导出保留尝试摘要和JSONL事件，采集阶段节流记录目标帧数、实际帧数、经过时间和最后进展。失败终态保留原始错误，附加日志写入失败不覆盖主错误。

排查ZIP只收集当前任务约定位置的近期诊断文件，明确缺失、截断和数量限制，拒绝链接目录，不包含DEM或媒体，不自动上传。日志是排查证据，不自动证明具体根因；原有固定超时策略本次保持。

桌面采用Tauri 2与React/TypeScript，解析、控制、采集等由Rust服务分层维护，前端负责有类型的交互和展示。
