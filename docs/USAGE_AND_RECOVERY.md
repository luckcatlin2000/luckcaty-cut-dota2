# 使用与故障恢复（2.5.0 待发布）

本说明面向独立高光主程序。原内置 WTF、剧情、录像分析与解说工作台已迁出；主程序不再使用“默认剪辑 / WTF 导演”双方案入口。WTF剪辑是单独的模块，与录像分析（完整名称为“猫猫的录像分析”）分开；该职责归属不代表独立模块已全部实现或公开。

## 运行前提

- Windows 10/11 x64；本地解析 DEM、选片、保存和导出排查包不需要运行 Dota 2。
- 导出真实画面需要 Steam 版 Dota 2。普通与干净画面都需要用户先手动登录并保持 Steam 运行；软件只检查进程，不启动、登录或控制 Steam。
- 正常退出自己已经打开的 Dota 2。软件拒绝接管已有客户端，用户确认开始导出或补录后才启动项目自己的离线进程。
- 官方安装版包含配套 FFmpeg/FFprobe。便携版需要保留工具目录或配置工具路径。
- 无需 OBS、模型额度、云端生成、BGM 或配音。发现更新时仅提示，是否下载安装由用户决定。

## 从录像到高光

1. 2.5.0 发布后，从官方 Release 安装 `luckcaty-cut-dota2_2.5.0_x64-setup.exe`。发布前以 Release 的实际附件为准，候选不等于已上线。
2. 选择、拖入本地 `.dem`，或设置录像目录后按编号载入。录像库首次进入读取目录，此后手动点击“刷新”；切换目录时读取新目录。软件不会按编号联网下载录像。
3. 解析完成后核对比赛信息与 10 人阵容，在“高光时刻”的“主角”页选择英雄，查看该英雄的击杀连续段。
4. 检查片段清单，新增、复制、删除或排序片段。删除只改变方案，不修改原 DEM；同场同步机位修改时间时保持相同入出点。
5. 在“时间”页设置入点与出点。每段为 1–100 秒，并须处于录像范围内；可输入 `HH:MM:SS.mmm`，或用秒级及帧级按钮调整。编辑网格为 30 Hz，导出视频为 60 FPS。
6. 击杀段可使用短击杀或更长的“剧情时长”。这里的剧情时长是保留动作铺垫的时间选项，不是旧剧情工作台。旧短击杀方案可点击“补足击杀铺垫”，保留当前片段与出点。
7. 逐段核对英雄与机位。玩家视角使用所选英雄玩家的视角；英雄跟随用于观察英雄动作，不等同于自由电影镜头或正面特写。选择普通或干净画面：普通保留游戏 HUD，只隐藏回放控制；干净画面隐藏 HUD 与指针。
8. 点击“导出视频”，复核文件名、源素材数量、成片时长与游戏原声，再点击“开始导出视频”。录制期间不要操作软件启动的 Dota 2。
9. 完成后在应用内播放，或打开成片与源素材目录。片段和镜头实际正确与否仍需查看画面，控制反馈不能代替人工确认。

主程序保留本地解析、击杀高光和人工编辑，不在这里生成树类候选、WTF 故事或分析报告。剧情与录像分析通过外接模块组合，点击时才发现已安装且兼容的模块；未安装时显示下载提示。没有随主程序提供的模块，不因按钮存在而视为已经可用。

## 输出和任务位置

优先使用“打开文件夹”“打开源素材”“打开已保存片段”，以及排查包完成后的“打开所在文件夹”，避免猜测安装版的数据目录。

| 内容 | 位置或命名 |
|---|---|
| 任务数据 | 便携版通常在软件目录的 `jobs/<任务编号>/`；安装版由应用管理 |
| 当前方案 | 任务内 `director/edit-plan.json` |
| 重新分析备份 | `director/edit-plan.before-reanalysis-<时间戳>.json` |
| 默认输出 | 任务内 `output/`，文件名沿用录像名称；重复导出追加 `_2`、`_3` |
| 自选交付目录 | 若在软件中设置成片位置，以完成页显示的实际路径为准 |
| 编号源素材 | `<成片文件名>_源素材/` 中的独立 MP4 与 `素材清单.json` |
| 恢复缓存 | 任务内 `render/cache/`；未合成时也可能已有完整切片 |
| 日志与尝试摘要 | 任务内 `render/logs/` 和 `render/attempts/` |
| 排查 ZIP | 用户在系统保存窗口中选定的位置，软件显示实际路径 |

同场 `S001-A/B/C` 等编号表示同步机位。备用机位保存在源素材中，不顺序追加到默认成片。原 DEM 保持只读；导出时可能在游戏回放目录准备经内容校验的副本。原生 JPG/WAV 临时素材位于游戏的录制目录，不一定与最终成片在同一磁盘。

## 草稿保全和断点续录

- 当前高光方案自动保存。切换任务、重新分析、更新和关闭前等待保存完成；保存失败会提示并保留工作区。
- 旧 WTF/剧情草稿保全但不自动执行。重分析前备份原方案，不为恢复入口而删除旧槽或用户素材。
- 同一 DEM 移动目录后可重新选择文件恢复任务；内容发生变化时拒绝混用旧分析与素材。
- 导出中断后保留原任务和原方案，从“最近任务”重新打开，再进入“导出视频”检查已保存片段。
- 查看已有 MP4，确认英雄与镜头正确后，明确选择“从第 N 段继续”。只补录缺失或未通过检查的片段；全部片段完整时可直接继续合成，无需启动游戏。
- “镜头未自动确认”与“媒体已完成”是不同状态。复用需要用户确认，不将控制台位置反馈视为自动识别英雄成功。
- 更改时间、顺序、机位、画面或采集管线会改变缓存身份。旧文件仍保留，但不保证任意旧版本都可直接续录。
- 取消后等待软件清理本次自有进程。关闭时若尚未确认退出，窗口会保留并提示；不接管或关闭用户自己启动的游戏。

## 失败后导出排查包

1. 等待当前录制完成收尾。
2. 在“导出视频”窗口点击红色“导出排查包”，选择 ZIP 保存位置。
3. 完成后点击“打开所在文件夹”，自行查看内容，再手动发送给维护者。软件不自动上传。

关闭并重开原任务后同样可导出历史记录，无需再次运行游戏。ZIP 包含当前错误说明、已有录制日志、早期失败/取消摘要、恢复状态与片段诊断，不含 DEM、图片帧、音频或视频。缺日志、截断和超限会明确说明；旧版没有保存的帧数进度无法补回。

排查包保存失败单独提示，不替换原录制错误；取消保存不生成文件，同名文件不会直接覆盖。浏览器界面预览无法导出 ZIP，请在桌面程序中操作。具体收集范围、容量和字段见 [排查包说明](DIAGNOSTIC_EXPORT.md)。

## 常见失败

| 现象 | 处理方式 |
|---|---|
| 需要若干帧，只得到若干帧 | 固定等待时间内未收齐目标帧数。导出排查包，依据帧数时间序列区分慢速推进和停滞；单个计数无法确定根因 |
| 游戏已运行 | 正常退出自己打开的游戏，再由导出操作创建独立离线进程 |
| 找不到 Dota 2 | 在设置中选择 `dota2.exe`；解析和编辑可继续使用 |
| 找不到 FFmpeg/FFprobe | 检查配套工具目录或路径；安装版可重新运行官方安装包 |
| 时间或英雄无效 | 核对当前录像、10 人阵容、时间范围和原方案，保留旧任务再处理 |
| 控制连接关闭或游戏意外退出 | 等待收尾，保留完整错误与本局排查包，不仅凭连接错误判断退出原因 |
| 更新失败 | 不影响本地解析和剪辑；等待当前任务结束后重试，不为更新强制中断录制 |

2.5.0 保留游戏原分辨率、60 FPS、JPEG 100 与原声。逐帧导出可能慢于实时，更多机位、高分辨率和长片段会增加耗时与磁盘占用。**本版没有修改既有固定超时策略，新增排查记录不等于该故障已解决。**

## 缓存管理与验证边界

完成页可检查可清理的原始 JPG/WAV，核对范围、数量与体积后再确认。清理保留全部 MP4、断点和诊断；删除原始帧不可撤销，再次从原始帧编码需重录。新素材优先硬链接共用内容，不支持时复制；外部编辑前另存独立副本。软件不自动迁移或删除旧视频。
