# 高光评分基线 v2

## 输入

检测器只读取版本化战斗时间轴，不直接依赖第三方解析器对象。英雄死亡在相邻间隔不超过 18 秒时聚为同一战斗；非击杀技术互动由精确事件链单独建立候选。

## 时间结构

- 铺垫：首个英雄死亡前 12 秒。
- 爆点：该战斗最后一次英雄死亡。
- 结果：爆点后 8 秒。

时间窗是第一版默认值，后续会根据技能施放、低血量状态、买活和建筑结果动态扩展。

## 英雄击杀连续段

每名已识别阵容英雄都会建立独立击杀索引：

1. 只接受该英雄取得击杀归属的真实英雄死亡事件，并排除会立即复活的假死亡。
2. 优先向前匹配造成击杀的同名技能释放，最长回看 20 秒。
3. 没有直接技能释放记录时，从该英雄对目标最近 8 秒内的交战起点开始。
4. 入点在起手事件前保留 1 秒，出点在最后一次击杀后保留 3 秒。
5. 同一英雄相邻击杀不超过 18 秒时合并，连续源时间最长 75 秒。

英雄击杀连续段不参与未选择主角时的通用导演排名；用户在 UI 选择高光主角后才按英雄载入。已验证技术互动与击杀段并列保留。

## 补刀斧拆树反制

当前第一条非击杀规则只在以下条件全部成立时触发：

1. 森海飞霞施放 `hoodwink_acorn_shot`，且目标为空，表示对地施法生成树。
2. 紧接着创建一个 `CDOTA_TempTree` 临时树实体。
3. 玩家对树发出 `DOTA_UNIT_ORDER_CAST_TARGET_TREE` 指令。
4. 同一 tick 附近出现该英雄的 `item_quelling_blade` 使用事件。
5. 被追踪的同一临时树实体随即删除。

每次命中生成独立短片候选，保存响应英雄、树实体句柄、创建/删除 tick、指定树指令、顺序、总次数、前 15 分钟顺序、响应延迟、附近的 `hoodwink_bushwhack` 和双方打赏次数。基础分由验证链、响应速度、附近捆人施法、打赏和同一英雄的重复次数组成；默认编排按时间保留全部已验证重复互动。

## 当前限制

- 已接入买活、Aegis 和建筑击杀；Roshan 击杀本体、胜负和经济反转仍需补充。
- 还未利用英雄低血量轨迹识别极限逃生或反杀。
- 还未使用画面检查确认技能是否在镜头内。
- 当前验证能证明同一临时树实体被删除，但不能保证镜头构图清楚展示树、补刀斧和人物动作；画面可读性仍需渲染后 QC 或人工复核。
- 分值是可解释基线，必须用人工标注集校准，不能直接当作最终审美模型。
