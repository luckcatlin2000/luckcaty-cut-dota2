## 日常使用

1. 打开录像，在制作台片段清单旁点“导入片段方案”。
2. 选择或拖入 Codex 提供的 JSON 文件，软件自动显示名称、起止时间、顺序和主角。
3. 勾选需要的片段，点“加入 N 个片段”。时间默认只显示，需要时才点“微调”。
4. 片段追加到当前方案，另一套方案保留。重复导入会跳过；当前会话可撤销本次新增，后来添加的其他片段保留。

也可在辅助页一次粘贴完整时间表，例如 `01:05—01:34｜第一次单杀影魔`，选择主角与时间依据后读取。JSON 自动使用文件中的主角和时钟。

返回制作台会保留本次预览；切换录像会清空预览。错误文件不允许采用上一份预览。保存失败不报告成功，不更新清单。

## 数据与加载

JSON 格式为 `d2h.timestamp-plan/1.0`：`match_id`、`hero`、`time_basis` 和 `clips` 必填；每段有 `id`、`title`、`start`、`end`，可带真实 `anchor.demo_tick` 与 `anchor.event_time_seconds`。支持来源 SHA-256 校验。

`game` 使用游戏计时，按本局比赛开始事件转换；`demo` 表示原始事件时间，不是录像 tick/30。每段 1—100 秒，一次 1—100 段，文件不超过 256 KB，JSON/TXT 使用 UTF-8。不能用估算 tick 冒充真实事件锚点。

实体解析失败会从头重读战斗日志，保留击杀、技能和时钟；结果明确标注缺少实体技巧，不虚构位置、连续走位或经济快照。新版缓存身份与旧版不同，首次加载可能重新分析；已有草稿保留。

本地 Codex 交接使用 `src-tauri/examples/import_timestamp_plan.rs`，调用同一验证与原子保存链；不是 MCP 或在线 API。候选支持 `--replay <DEM路径>` 打开指定录像。导入、分析与保存不会启动 Dota 2。
