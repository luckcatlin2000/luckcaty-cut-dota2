# 2.3.9 剧情每段英雄与一次导入

> 历史本地候选与用户验收记录，不是当前高光发行版提供剧情模块的声明。原录像、录制方案、候选任务副本和验收资料保存在私有归档。

本次仅修用户点名的剧情主角覆盖和单文件导入限制。2.3.8 第一段火猫镜头已经由用户实测确认正确，renderer 与 replay-control 保持该版本的文件内容。

## 使用

1. 双击 `release/candidate/2.3.9/猫猫的剪辑小助手_2.3.9_portable.exe`，候选附当前本局六段草稿的独立副本。
2. 点击当时的“导入剧情片段方案”，选择匿名历史样本的完整八段多主角方案。该私有录制方案不随源码提供。
3. 当前六段副本中，预览会跳过三个已正确的火猫片段，提示新增两段参团、修正水人/蓝胖/收尾三段的录制英雄。确认后为原八段顺序、总长 02:53。时间、视角、已有片段编号及勾选保持。
4. 每行“录制英雄”只改该行。右侧“新增片段默认英雄”用于新增时间片段，不改现有行。导出预览逐行显示实际英雄。
5. 已录火猫素材仍在原 2.3.8 任务目录，未移动或覆盖。后续只勾选需要录制的片段；候选独立任务不自动合并旧目录的录制缓存。

导入修正支持“撤销本次剧情导入”：移除本次新增行，恢复本次改过的英雄；后续手工修改的时间/视角保留。若用户之后又手动更换了英雄，撤销不会再覆盖那次选择。

## 文件合同

新文件使用 `d2h.timestamp-plan/1.1`。顶层 `hero` 为缺省英雄；每条 `clips[]` 的可选 `hero` 覆盖该条，省略时继承顶层。每个英雄必须属于当前录像阵容，每条仍独立核验时间、源文件和事件锚点。原 `1.0` 与 TXT 继续支持。

新格式仅供 2.3.9 及以后的兼容程序，旧版会拒绝该版本，避免悄悄按一个英雄导入。当前不增加 MCP/API、自动文案或配音功能。

## 验证与交付边界

完整离线退出 0：186 项 Rust、90 项前端；新 UI 11 项、旧剧情 25 项、时间表 13 项，0 页面异常。GUI 候选编译完成，Windows 文件/产品版本 2.3.9，与构建文件哈希一致。页面使用 DEV 专用夹具；真实数据导入仅修改隔离副本，不启动游戏。完整结果和候选元数据保存在私有验收归档。

完整八段方案的英雄为前五段火猫、第六与第八水人、第七蓝胖，共八段 173 秒；用户可以自行删段和更改录制英雄。原任务、镜头缓存、视频和 DEM 保留。
