# 独立软件与剪辑助手的录制交接

本轮只内置高光录制，支持普通画面与干净画面。WTF剪辑为独立模块，与录像分析分开，剧情制作由相应独立软件承担；界面保留独立WTF、剧情与录像分析外接按钮和下载提示。按钮并不表示已经安装或连接，当前没有发布下载地址。

## 分工与扩展方式

外部软件提供选择好的录像片段；剪辑助手校验录像身份与时间，使用已有录制、机位、HUD、原声和合并能力。新增一种软件只需提供软件描述和协议适配，无需在录制核心新增一种“WTF 模式”或另一份录制实现。

外接工具使用稳定 id、显示名称和可用状态描述；界面提示统一处理。当前内置的占位项目是配置项，后续其他软件沿用同一机制。

## 已有的片段交换格式

### 本地模块按需打开

2.5.0按需查找EXE主目录的直接子文件夹`module.json`，不定时扫描。已安装模块使用以下清单：

```json
{"protocol":"maomao.module/1","id":"maomao.replay-analysis","toolId":"analysis","name":"猫猫的录像分析","version":"0.1.0","entry":"猫猫的录像分析.exe"}
```

入口限定安装目录内的EXE，通过`--root <模块目录>`启动；不执行清单中的任意shell命令。未安装、接口不兼容或重复安装会明确提示。WTF入口由独立WTF模块承载，与analysis使用不同的模块标识；其它独立软件沿用同一机制，不改变录制核心。

分析界面由独立的本地服务在浏览器显示，点击分析按钮会自动按需打开，用户不用预先手动启动两个软件。勾选交接由固定桥接工具验证后创建独立会话，并打开剪辑助手供确认，不自动录制。

优先沿用实际校验器支持的 `d2h.timestamp-plan/1.1`；保留对 1.0 的兼容。示意数据使用虚构比赛和片段，不含用户素材：

```json
{
  "schema_version": "d2h.timestamp-plan/1.1",
  "match_id": "42",
  "hero": "npc_dota_hero_mirana",
  "time_basis": "game",
  "source": { "sha256": "由适配器填写实际DEM的SHA256" },
  "clips": [
    {
      "id": "scene-001",
      "title": "片段一",
      "start": "12:10.000",
      "end": "12:24.000"
    }
  ]
}
```

这是字段示例，使用时必须填写实际文件哈希、比赛编号和本局英雄。`game` 表示游戏时钟，`demo` 表示录像事件时间；校验器负责按本局比赛开始事件转换，适配器不能把二者混用。每行可指定 `hero`，以及由真实录像事件产生的 `anchor`（`demo_tick` 与 `event_time_seconds`）。

当前格式最多 100 个片段，每段 1–100 秒，文本最多 256 KiB。会校验协议版本、比赛编号、可选源哈希、英雄阵容、时间范围、重复标识及事件锚点。对接时应始终传入实际源哈希。错误返回可读原因，不靠文件名或某个软件名字猜测。

## 内部适配步骤

1. 高光导入/解析取得当前录像任务；原始 DEM 保持只读。
2. `preview_timestamp_plan` 接收 `jobId` 与 `path` 或 `text`，返回规范化片段；跨软件时通过适配器调用，不能直接把未校验数据交给录制器。
3. 通过现有 `save_edit_plan` 保存默认方案；英雄、机位、普通/干净画面等使用原有片段和 `RenderSettings` 字段，避免在时间表协议里临时发明字段。
4. 由正常导出操作进入 `start_render`；状态与续录由现有任务状态和 `get_render_resume` 提供。

后端保留通用 Rust 函数 `import_timestamp_file(replayPath, planPath, jobsRoot)`，将独立方案导入高光草稿并返回交接回执。此函数不启动游戏。

上述 Tauri 命令和 Rust 函数是剪辑助手内部接入点，不是MCP服务。分析模块另提供仅本机的HTTP界面服务，通过固定桥接程序转成隔离录制任务。后续MCP/API适配层沿用同一任务和回执；当前不接模型或自动下载软件。

## 数据兼容

本轮只执行默认高光方案。旧 WTF/剧情草稿不自动加载执行；保存高光时保全已有 WTF 槽，重分析前备份旧草稿。原来的多功能实现另有本地源码备份，不能通过恢复一个按钮重新加载整套分析代码。

## WTF同步机位方案1.2

携带主备同步机位的独立WTF方案使用d2h.timestamp-plan/1.2。新增camera_mode、take_group_id、take_role、include_in_final，主机位唯一且默认入片，备用不入片，同组时间和事件保持一致。1.0/1.1合同保持兼容，不静默接受1.2专用字段。交接使用独立会话，不能把备用拍摄时长追加到成片。实现状态见[WTF模块](WTF_MODULE.md)。
